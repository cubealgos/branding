# Security Policy

## Supported versions

Security fixes are applied to the latest commit on `development` and to the most recent release on
`production`.

## Report a vulnerability privately

Email **security@cubealgos.de** with "Security: branding" in the subject. Do not disclose a
suspected vulnerability in a public issue, pull request or comment before coordinated disclosure.

Include as much of the following as you can:

- the affected file, script or workflow;
- a description of the impact and who could be affected;
- clear reproduction steps or a minimal proof of concept;
- a suggested mitigation, if you have one.

Avoid including secrets, credentials or personal data in the report.

## What to expect

Acknowledgment as soon as practical, validation, scoping, and coordinated remediation and
disclosure with the reporter.

## Good-faith research

Avoid accessing, modifying or deleting data that does not belong to you, or disrupting services.
If testing could affect other people or systems, stop and submit a private report first.
